## Фаза 1 — что уже сделано

Сменена палитра в `cabinet/index.html` (`:root` + два box-shadow). Имена CSS-переменных оставлены прежними, чтобы не править весь файл. Конкретно:

| Переменная | Было (dark) | Стало (light) |
|---|---|---|
| `--dark` | `#08090c` (главный фон) | `#ffffff` (белый) |
| `--dark2` | `#0f1014` (топбар, сайдбар) | `#fafaf7` (тёплый кремовый) |
| `--dark3` | `#161820` (акценты/hover) | `#f1efea` |
| `--surface` / `--surface-2` | тёмно-синие тона | `#ffffff` / `#fbfaf7` |
| `--surface-3` | `rgba(255,255,255,.05)` | `rgba(0,0,0,.04)` |
| `--t1` (основной текст) | `#f0ede8` (светлый) | `#1a1a1a` (тёмный) |
| `--t2` (вторичный текст) | `#a8a49e` | `#5a5550` |
| `--t3` (плейсхолдер) | `#5c5854` | `#9c958c` |
| `--b1` / `--b2` (бордеры) | белые с альфой | чёрные с альфой |
| `--ok` / `--warn` / `--alert` | светлые оттенки | более насыщенные для светлого фона |
| Box-shadow на `.gate-box` и `.modal-content` | `rgba(0,0,0,.6)` | `rgba(0,0,0,.10–.18)` (мягкие) |

**Что НЕ менялось:**
- Золотая палитра (`--gold*`) — сохранена как акцент, работает и на светлом, и на тёмном.
- Чёрный текст на кнопках с золотым градиентом (`color:#000` в `.gate-btn`, `.modal-action`) — корректно для обеих тем.
- Модальный backdrop `rgba(0,0,0,.7)` — корректно затемняет страницу за модалкой.

## Фаза 2 — что нужно продумать отдельно

### 2.1 Контент и поток нутрициолога
- Какие конкретно сценарии работы нутрициолог покрывает в кабинете? Сейчас в HTML видно: список клиентов в сайдбаре, форма редактирования клиента, поиск.
- Какие данные критичны и должны быть на первом экране? (анкета? показатели? недельные тренды? даты сессий? напоминания?)
- Как связать кабинет с потоком из `program-intake` (KV `PROGRAM_INTAKES` в Worker), чтобы автоматически появлялись новые клиенты после оплаты?
- Аналогично — связь с потоком EXPERT/ELITE-разборов из ИП (KV `EXPERT_DRAFTS`, статус разборов).

### 2.2 Хранение (главное технологическое решение)
- **Сейчас:** данные клиентов в `localStorage` одного браузера. Если устройство сломается / нутрициолог зайдёт с другого — все клиенты пропали. **Это бомба, если запустить как есть.**
- Варианты:
  - **A. Google Sheets бэкенд** — клиенты в отдельном листе, как коды; читаем через Apps Script. Дёшево, естественно вписывается в текущий стек, нутрициолог может смотреть/править лист напрямую.
  - **B. Cloudflare KV** — отдельный namespace `CLIENTS`, читаем-пишем через новый эндпоинт Worker. Быстрее, но Google Sheets для нутрициолога удобнее как фоллбэк-UI.
  - **C. Notion / Airtable** — внешняя CRM с API. Гибче, но добавляет ещё одну подписку и зависимость.
- **Предложение по умолчанию:** A (Google Sheets) — переиспользует существующую инфраструктуру; нутрициолог уже работает с таблицей кодов.

### 2.3 Аутентификация
- Сейчас на входе `#gate` с паролем. Какой пароль, где хранится, как сменить? Один пароль на одного нутрициолога — норм, но нужно подтвердить.
- Если кабинет хостится на github pages — пароль в HTML-исходнике публичен. Минимум: переместить проверку в Worker (POST `/cabinet-auth` с rate-limit).

### 2.4 Дизайн (после контента и хранения)
- Типографика: серый текст `--t2: #5a5550` на белом — нужно проверить контраст по WCAG AA (вроде проходит, но визуально может быть слишком блёкло).
- Сайдбар-клиенты: нужны бейджи статуса (новый / активный / завершён / просрочен), визуальная сортировка по приоритету.
- Карточка клиента: вкладки (анкета / биометрия / разборы / сессии / заметки)?
- Pagination/поиск по списку клиентов при росте базы (>50 клиентов).
- Mobile-вариант — нутрициолог может работать с iPhone? Если да — сайдбар-друвер.

### 2.5 Связки с остальным проектом
- Кнопка «Сгенерировать новый код доступа ИП» прямо из карточки клиента (Apps Script `assign_code` + автоматическое присвоение).
- Кнопка «Отправить программу-приглашение» — то же, что Hotmart-webhook делает сейчас при оплате (ссылка на `program-intake.html?t=…`).
- Просмотр последнего AI-разбора клиента (KV `EXPERT_DRAFTS` + `PROGRAM_INTAKES` через Worker).
