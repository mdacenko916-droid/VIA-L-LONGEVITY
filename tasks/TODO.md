## 2.5. Платформа для многих специалистов ← СЛЕДУЮЩИЙ БОЛЬШОЙ

**Спека на согласовании с владельцем (2026-06-06, уточнена) → [`docs/PLATFORM-MODEL.md`](../docs/PLATFORM-MODEL.md).**
ИП как инструмент для смежных специалистов (гинеколог/эндокринолог/андролог вокруг
пред-менопаузы/андропаузы): специалист рекомендует гаджет → клиент берёт **месячную подписку
PRO** → специалист ведёт его из кабинета (биометрия + ИИ-разборы). Живой эксперт = его врач;
**EXPERT/ELITE остаются воронкой основателя.** Монетизация: клиент платит подписку, специалист —
**абонентскую плату за доступ к платформе.** Принцип — готовое не ломаем: текущий нутрициолог =
«специалист №1».

Ключевое изменение правила: **PRO теперь заводит карточку**, если клиент пришёл по рефералу
специалиста (`ref_code`) → привязка `clients.specialist_id`. Сущности: `specialists`
(+`access_status`/`ref_code`/`lang`) + колонка `specialist_id` у клиента + мост перевода.

Этапы (спека §8): ✅ 1 фундамент → ✅ 2 подключение пациента (`/specialist/connect|unlink`) →
✅ 3 вход+видимость (логин PBKDF2, сессия {id,role}, 403) → ✅ 4 абонплата
(`/specialist-access-webhook` Hotmart + cron-истечение + email специалиста) → ✅ 5 мост перевода
(`/cabinet/translate`, ИИ-черновик на языке специалиста, авто-перевод при отправке, кнопки
«Перевести») → ✅ 6 панель владельца (`/cabinet/specialists|*`, вид «🩺 Специалисты»).

**ВСЕ ЭТАПЫ ПЛАТФОРМЫ 1–6 ЗАВЕРШЕНЫ И В ПРОДЕ.** Языки: 12 структурных (uk/ru/en/es/de/pt/fr/
pl/it/he/ja/ko); сам переводчик (Claude) не ограничен 12. he/ja/ko/ar → Sonnet.

### Локализация кабинета на 12 языков (→ продаваемый продукт для специалистов) ← В РАБОТЕ
Цель (решение владельца 2026-06-06): перед продажей подписки специалисту кабинет должен быть
полностью готов — интерфейс на языке специалиста (12 языков), без «допилим потом». Делаем
аккуратными партиями, каждая сразу на 12 языков; язык по умолчанию = язык специалиста
(`/cabinet-auth` отдаёт lang), владелец-ru не замечает миграции (фолбэк на ru).
- ✅ **Партия 1 (2026-06-06):** движок i18n (`T` key-major, `t()`, `applyI18n()` по data-i18n,
  переключатель языка), экран входа, верхняя навигация, 9 вкладок. `/cabinet-auth`→lang.
- ✅ **Партия 2 (2026-06-06):** окна клиента и специалиста (поля/опции/кнопки/заголовки),
  боковая панель (поиск/фильтр/сортировка), статусы клиента (`st_*` + `statusLabel()`).
- ✅ **Партия 3a (2026-06-06):** вкладка «Обзор», шапка карточки (мета/Старт/кнопки), панель
  «Специалисты» (таблица/бейджи/подсказки); helpers phaseLabel/specialtyLabel.
- ✅ **Партия 3b (2026-06-06):** Биометрия, Сессии, Разборы, Переписка (+статусы кнопок ИИ/отправки).
- ✅ **Партия 3c (2026-06-06):** Протокол, Анализы (19 показателей+группы+статусы), Заметки,
  Анкета, Календарь, список (всего/пусто/ещё), все confirm/alert + SPEC_ERR.
- ⏳ **Остаток (партия 3d):** (1) экспорт **PDF** (`generatePDF`) — шапки отчёта на русском, нужно
  локализовать (для PDF-формата ведения лучше на язык пациента); (2) сид «Базовый протокол по полу»
  (`addDefaultProtocol`) — названия добавок русским сидом (редактируемые). Всё остальное в UI — на 12.
- Потом: PWA (значок на экран, телефон/планшет — ВОПРОС владельца); RTL для иврита; вид под
  профиль (не-нутрициолог). Кабинет специалиста = веб-PWA; магазинное app — это ИП пациента.
- Контекст: модель работает и офлайн (местные специалисты), и **онлайн** (специалисты по миру,
  как владелец в EXPERT/ELITE — там перевод/12 языков становятся ядром, см. [[project_platform_specialists]]).

Остатки (не блокеры, по готовности):
