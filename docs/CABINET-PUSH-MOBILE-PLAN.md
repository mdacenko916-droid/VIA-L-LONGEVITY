# Кабинет специалиста: непрочитанные, пуш и телефонный режим — план

**Дата:** 2026-09-25. **Решение владельца:** делать (пункт 2); пуш клиенту в приложение — пункт 3, версия 1.0.8.
**Связано:** [APP-SPECIALIST-LINK-PLAN.md](APP-SPECIALIST-LINK-PLAN.md) (переписка клиент ↔ специалист),
[PLATFORM-MODEL.md](PLATFORM-MODEL.md).

## 0. Проблема

Клиент из приложения пишет специалисту (текст, фото, голос) — специалист **ни о чём не узнаёт**:
пинг уходит только в Telegram-топик, а у клиентов из приложения топика нет (проверено на тестовой
карточке `PHWTRPL`). Непрочитанных в кабинете нет: сообщение видно, только если открыть карточку.
Кабинет — PWA (манифест `standalone`), но свёрстан под компьютер: на телефоне тесно.

Почту владелец отклонил: при многих клиентах письма станут спамом.

## 1. Что делаем

| Часть | Где | Что |
|---|---|---|
| Счётчик непрочитанных | D1 `clients.unread` | +1 на каждое сообщение клиента, 0 — когда специалист открыл переписку (`/cabinet/chat-read`) |
| Подписки специалиста | D1 `spec_push` (endpoint, spec_id, peek, lang, fails) | браузер/телефон специалиста, на который слать пуш |
| Пуш специалисту | воркер, `handleExpertMessage` | пуш **без тела** (как у EXPERT): на серверах Apple/Google ни слова о клиенте |
| Надпись пуша | `GET /cabinet/push-peek?t=<peek>` | service worker по одноразовому секрету подписки берёт «Анна · голосовое» — имя и вид, без данных о здоровье |
| Открытие по нажатию | `cabinet/sw.js` → `/cabinet/?open=<code>` | кабинет открывается сразу в переписке с этим клиентом |
| В кабинете | `cabinet/index.html` | «💬 N» у клиента, общий счётчик сверху, число в заголовке вкладки, опрос раз в минуту, кнопка «Включить уведомления» |
| Телефонный режим | `cabinet/index.html` | на узком экране: список клиентов с непрочитанными → переписка на весь экран → коротко карточка |

## 2. Ограничения

- **iPhone:** веб-пуш приходит только в кабинет, **добавленный на экран «Домой»** (iOS 16.4+). Кнопка
  включения уведомлений в браузере Safari на iPhone так и скажет. Android и компьютер — в любом браузере.
- Пуш без тела: текст собирает service worker, запрашивая `push-peek`. Нет сети в момент пуша — покажет
  нейтральное «Новое сообщение от клиента».
- Секрет `peek` живёт в подписке и знает только своего специалиста; отдаёт имя последнего написавшего
  клиента и вид сообщения — ничего больше.

## 3. Пуш клиенту в приложение (пункт 3, версия 1.0.8)

Нативные пуши: ключ APNs (developer.apple.com → Keys → Apple Push Notifications service), проект
Firebase для Android (`google-services.json`), плагин `@capacitor/push-notifications`, разрешение
`aps-environment`, серверная отправка APNs (HTTP/2, JWT) и FCM v1. Нажатие — «Мой наставник» → переписка.
В 1.0.7 не входит: новое разрешение в сборке, а 1.0.7 уже готова к подаче.
