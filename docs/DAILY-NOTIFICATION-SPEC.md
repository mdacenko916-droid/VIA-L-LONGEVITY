# Ежедневное уведомление VIA-L — ТЗ

**Дата:** 2026-08-26. Идея владельца: утром человек получает то, что вчера попало в «Памятку дня» —
как проснуться, вода, разминка, тарелка. Ниже — как это сделать, чтобы уведомление помогало, а не
раздражало и не разглашало здоровье.

---

## 1. Локальные, а не серверные

Берём **локальные уведомления** (`@capacitor/local-notifications`), которые планирует само
устройство. Причины: не нужен сервер и APNs-сертификаты, работает без сети, ничего не стоит и не
добавляет ни строчки в метки приватности — данные никуда не уходят.

Серверные пуши понадобятся только если однажды захотим слать что-то извне (например, специалист
написал в чат) — это отдельная задача и отдельная инфраструктура.

Ограничение платформ: в нативном приложении работает везде; в PWA на Android — да, на iOS — только
если PWA установлена на домашний экран. То есть канал полноценно живёт в App-Store-сборке.

## 2. Главное ограничение — экран блокировки

**Текст уведомления видят посторонние.** Человек в метро, коллега рядом, ребёнок взял телефон.
Поэтому:

- В тексте **нет ничего о здоровье**: ни приливов, ни давления, ни сна, ни менопаузы, ни веса,
  ни названий состояний и анализов. Даже того, что VIA-L разрешено писать внутри приложения.
- Разрешены только бытовые действия: вода, движение, завтрак, «план дня готов».
- Всё содержательное — **за нажатием**, внутри приложения, где стоит обычный гейт.

Это не перестраховка: приложение про менопаузу и андропаузу, и надпись на заблокированном экране
может выдать человека помимо его воли.

## 3. Что несёт уведомление

**Одно действие, не распорядок.** На экране блокировки видно заголовок и две-три строки; четыре
пункта туда не влезут, а если влезут — их не прочитают.

Из «Памятки дня» берём **только устойчивую часть** — воду, разминку, завтрак. Подстроенное под день
(«сегодня отложите тяжёлое, восстановление ниже обычного») в утренний пуш **не кладём**: оно
посчитано по вчерашнему восстановлению и утром уже неправда.

Пример: заголовок «Доброе утро», текст «Стакан воды и пять минут движения — и завтрак с белком».

## 4. Правила показа

| Условие | Поведение |
|---|---|
| Проход за сегодня уже сделан (`vialp_lastpass` = сегодня) | уведомление **не приходит** |
| Последний план свежее 3 дней | текст из плана (устойчивая часть) |
| План старше 3 дней или его нет | нейтральное «Отметьте, как прошла ночь» |
| В выбранном пункте нашлось «здоровое» слово | падаем на нейтральный текст — молча, без попытки переписать |
| Время | по умолчанию **08:00**, меняется в «Моём профиле»; часовой пояс — устройства |
| Частота | **строго одно в день**. Второе (вечернее) — только явным включением, фаза 2 |

Нажатие открывает приложение на вкладке «Сегодня» с раскрытой утренней карточкой:
`?tab=today&plan=morning` — обработчик `?tab=` уже есть (`interpreter-via-l.html`, «Возврат со
страницы Мой наставник»), добавить разбор `plan=`.

## 5. Откуда берём текст

- План: `vialp_day_plan` → `_dpGet()[0]` (массив `{day, lang, sig, plan}`), секция `morning`,
  первый пункт из первой секции.
- Язык: из того же слепка (`lang`), а не текущий — если человек сменил язык, текст пересоберётся
  при следующем открытии приложения.
- **Фильтр экрана блокировки** (новый, отдельный от велнес-фильтра воркера): стоп-список слов —
  прилив, жар, потливость, менопауза, андропауза, гормон, давление, пульс, сон/бессонница, вес,
  талия, анализ, дефицит, тревога, либидо + названия состояний из `COND_GROUPS`. Нашлось хоть одно —
  нейтральный текст. Проверять на всех 12 языках нельзя списком слов, поэтому:
  **для языков, кроме ru/uk/en, сразу используем нейтральный текст** (честнее, чем надеяться).

## 6. Разрешение на уведомления

Спрашивать **не при первом запуске**, а после того, как человек получил первую «Памятку дня» —
тогда просьба понятна: «Присылать утром одно короткое напоминание из вашей памятки?». Отказ
запоминаем и больше не спрашиваем.

Android 13+ требует `POST_NOTIFICATIONS`; iOS — обычный запрос разрешения. В метках приватности
App Store ничего не меняется: данные не собираются и не передаются.

## 7. Этапы

1. `npm i @capacitor/local-notifications` + `npx cap sync`; плагин добавляется в существующую сборку.
2. `interpreter/notify-bridge.js` по образцу `iap-bridge.js`: `notifyAvailable()`, `notifyAsk()`,
   `notifySchedule(hhmm, title, body)`, `notifyCancel()`. На вебе — no-op.
3. Сборщик текста в клиенте: `_notifyText()` — план → устойчивый пункт → фильтр → фолбэк.
4. Планирование: при каждом открытии приложения и после каждого прохода отменяем и ставим заново
   на завтра (текст мог измениться). Повтор — ежедневный, но перепланирование даёт свежий текст.
5. Настройка в «Моём профиле»: переключатель и время, рядом с блоком приватности.
6. `?plan=morning` в обработчике вкладок.

Разработку и проверку можно вести **на симуляторе** — локальные уведомления там работают, $99 для
этого не нужен (нужен для TestFlight и живого устройства).

## 8. Фаза 2 (не сейчас)

Вечернее напоминание тем, кто не прошёл за день, — только по явному включению. Два уведомления в
день это граница, за которой приложение начинают отключать целиком.
