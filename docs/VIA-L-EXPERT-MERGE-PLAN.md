## ДВА РАЗДЕЛЬНЫХ ПРОДУКТА (канон владельца 2026-07-25) — почему клон обязателен

1. **VIA-L** — приложение App Store + Google Play. **Герметично:** все концы с сайтом ОБРУБЛЕНЫ,
   полный велнес (1.4.1), без мед-терминов, без Hotmart/кабинета/ссылок на сайт. Файл `interpreter-via-l.html`,
   обёрнут Capacitor. Шлёт воркеру `tier:'pro'` → велнес-промпт. **Больше НИЧЕГО EXPERT в него не добавляем.**
2. **VIA-L EXPERT** — веб/Hotmart. Клиника (мед-термины разрешены), завязан на сайт via-l нутрициолог +
   кабинет нутрициолога. Файл `interpreter-via-l-expert.html` (клон). Шлёт `tier:'elite'` → клин. промпт.

**Вывод: Вариант А (отдельный файл-клон) — НЕ выбор стиля, а ТРЕБОВАНИЕ комплаенса.** Один файл на оба
режима (переключение по коду) отвергнут: магазинная сборка не должна физически содержать код клиники/
Hotmart/кабинета/сайта (риск отклонения Apple/Google 1.4.1 + внешняя оплата). Две сборки = физически раздельны.
Дублируется ТОЛЬКО форма опросника (правки формы — в оба файла); «мозги» (KB/паттерны/промпты) в воркере, общие.
Воркер уже переключает режим по `tier` (`isWellness = ['vio','pro'].includes(tier)` — иначе клиника).

## Цель (канон владельца 2026-07-25)

  Дублируется только HTML-проход (форма опросника) → правки формы вносить в оба файла.
- **Проход (UX/анкета/интерпретатор)** = via-l-проход, КАК ЕСТЬ (в клоне).

1. **Продукт/страница «PRO+EXPERT €79»** → **УДАЛИТЬ.** (product 7838826, `interpreter-pro-expert.html`,
   ссылка `K106049657S`, карточка в index, коды VIAL-EXPERT, apps-script EXPERT-подписка.)

   отчёт в карточку) → **ОСТАВИТЬ.** Именно им работает новый VIA-L EXPERT. Комментарии/ветки
   «EXPERT/ELITE» в воркере, описывающие клинику, НЕ трогать (они теперь про VIA-L EXPERT).
