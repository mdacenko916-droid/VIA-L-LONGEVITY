# Подписка в Google Play: продукт → RevenueCat → код

**Заведено 2026-09-07.** Цена подтверждена владельцем: **€30/мес**. Она обязана совпадать в
четырёх местах — продукт в Play, продукт в App Store Connect, комментарий в `iap-bridge.js`
и раздел «Подписка» во ВСЕХ описаниях витрин (`PLAY-LISTING-EN.md`, `PLAY-LISTING-LOCALES.md`).

Порядок обратный не работает: снять `TEST_BYPASS_PAYWALL` раньше, чем заработает биллинг, —
значит повторить историю с iPhone, где живое устройство упиралось в незакрываемый пейволл.

---

## Шаг 1. Продукт в Play Console (делает владелец)

**Монетизация → Продукты → Подписки → Создать подписку.**

| Поле | Значение |
|---|---|
| Идентификатор продукта | `via_l_pro_monthly` |
| Название | `VIA-L` |
| Описание | короткая фраза, её видно в списке подписок Google Play |

Внутри продукта — **базовый план**:

| Поле | Значение |
|---|---|
| Идентификатор плана | `monthly` |
| Тип | автопродление |
| Период оплаты | 1 месяц |
| Цена | 30 € (Google пересчитает по странам — доллар проверить глазами) |
| Пробный период | нет (добавляется позже отдельным предложением, пересборка не нужна) |

Идентификаторы менять нельзя после публикации — Google их не отпускает.

## Шаг 2. Сервисный аккаунт (самое долгое — начинать заранее)

RevenueCat для Android нужен не ключ, а сервисный аккаунт Google Cloud с правами в Play.
**Права расходятся до 36 часов** — пока не разошлись, RevenueCat отвечает ошибкой доступа,
и это нормально, а не поломка.

1. **Google Cloud Console** → проект (любой, можно новый) → «IAM и администрирование →
   Сервисные аккаунты» → создать. Роли на этом шаге НЕ нужны.
2. У созданного аккаунта → «Ключи → Добавить ключ → Создать ключ → JSON». Файл скачается один
   раз, второй раз его не выдадут. **В репозиторий не класть.**
3. **Play Console → Пользователи и разрешения → Пригласить пользователя**: адрес сервисного
   аккаунта (вида `...@....iam.gserviceaccount.com`). Права на приложение VIA-L:
   просмотр сведений, управление заказами и подписками, управление финансовыми данными.
4. **Google Cloud → API и сервисы → Библиотека** → включить **Google Play Android Developer API**.

## Шаг 3. RevenueCat

1. Проект VIA-L → **Add app → Google Play**, package `com.viael.vial`.
2. Загрузить JSON из шага 2 в поле Service Account credentials.
3. **Entitlement `via_l_pro`** — тот же, что у iOS. Не заводить второй: код проверяет именно
   его, и человек, купивший на телефоне, должен получить доступ везде.
4. **Offering `default`** → package Monthly → продукт `via_l_pro_monthly:monthly`.
5. Скопировать **Android public SDK key** (начинается на `goog_`).

## Шаг 4. Код (делает Claude)

В `interpreter/iap-bridge.js`: добавить ключ Android рядом с iOS (выбор по платформе через
`Capacitor.getPlatform()`), затем снять `TEST_BYPASS_PAYWALL` — в том же коммите, не раньше.

## Шаг 5. Проверка покупки без списания денег

**Play Console → Настройки → Лицензирование** (аккаунт разработчика, не приложение) → добавить
адреса тестировщиков. Они проходят весь путь оплаты по-настоящему, но деньги не списываются, а
подписка продлевается ускоренно (месяц ≈ 5 минут) — удобно проверить и продление, и отмену.

Проверить обязательно: покупка, «Восстановить покупки» на втором устройстве, отмена в Play и
поведение приложения после окончания оплаченного периода.
