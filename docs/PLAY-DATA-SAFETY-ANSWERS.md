# Google Play → «Безопасность данных»: ответы для VIA-L (`com.viael.vial`)

Составлено 2026-09-03 по коду `interpreter/interpreter-via-l.html`, `interpreter/cloudflare-worker.js`
и `app/package.json`. Анкета заполняется один раз и правится при каждом изменении потоков данных.
Ответы должны совпадать с политикой (`legal-app/privacy.html`) — расхождение = отказ на ревью.

## Что уходит с устройства (факты из кода)

| Куда | Когда | Что именно | Хранится ли |
|---|---|---|---|
| `/day-plan`, `/weekly-report`, `/ai-memory` | при разборе | показатели трекера + ответы опросника + профиль (пол, возраст, фаза) | входные — нет; **готовый разбор 72 ч** в KV `an:<cid>:<день>` |
| `/advisor-chat` | в чате | текст сообщений пользователя + контекст | нет (история только на устройстве) |
| `/research/day` | только при включённом согласии | обезличенный дневной срез, whitelist на сервере, свободные тексты не принимаются | да, D1 `research_days`, ключ — случайный `pid`, удаление по `/research/forget` |
| RevenueCat | при покупке/восстановлении | факт подписки, идентификатор установки | у RevenueCat |
| D1 `ai_usage` | каждый вызов | токены и стоимость, **без данных пользователя** | да |

Аккаунтов, аналитики, крашлитики и рекламных SDK нет.

## Шаг 2 — «Сбор и безопасность данных»

- **Собирает ли приложение данные?** → **Да**. (Даже если сервер не хранит вход, передача с устройства
  = сбор по определению Google.)
- **Шифруются ли данные при передаче?** → **Да** (только HTTPS).
- **Можно ли запросить удаление данных?** → **Да**. Аккаунтов нет: всё локальное удаляется вместе с
  приложением, вклад в исследование — кнопкой в приложении (`/research/forget` по `pid`).
- **URL удаления аккаунта** → не заполняется: механизма аккаунтов нет.

## Шаг 3 — типы данных

Для каждого типа: **Собираются — да**, **Передаются третьим лицам — нет**
(Cloudflare, Anthropic и RevenueCat действуют как обработчики по нашему поручению — это
исключение «service provider» в правилах Google), **Обрабатываются только временно — нет**
(из-за 72-часового кэша разбора), **Обязательные** (кроме отмеченных).

1. **Информация о здоровье** — ВСР, пульс покоя, пульс, сон, SpO₂, температура, VO₂ max,
   давление, симптомы (приливы), добавки и анализы, самочувствие.
   Цель: *функциональность приложения*, *персонализация*.
2. **Информация о физической форме** — шаги, активность. Те же цели.
3. **Личная информация → Другие данные** — пол, возраст, фаза цикла, цель.
   Цель: *функциональность приложения*, *персонализация*.
4. **Сообщения → Другие сообщения в приложении** — свободный текст в чате с ассистентом и
   жалоба «с чем пришёл». Цель: *функциональность приложения*.
5. **Финансовая информация → История покупок** — подписка через Google Play/RevenueCat.
   Цель: *функциональность приложения*. Обязательные.
6. **Идентификаторы устройства или другие** — случайный идентификатор установки (RevenueCat;
   `pid` для исследования). Цель: *функциональность приложения*.
   Для `pid` пометить **необязательные** — синк выключен по умолчанию.

Не отмечать: местоположение, контакты, календарь, фото, аудио, файлы, историю поиска и
просмотров, СМС, данные об установленных приложениях, крашлоги и аналитику — ничего этого нет.

## Что должно совпасть с политикой

Политика сейчас пишет обобщённо: «данные, которые вы разрешили читать из Apple Health /
Health Connect». Google требует **поимённого** перечня типов Health Connect и цели по каждому.
Правка `legal-app/privacy.html` × 12 языков ждёт слова владельца (юридический текст) —
см. `tasks/TODO.md` и `docs/ANDROID-PLAY-LAUNCH-PLAN.md`.

Список для политики: ВСР (HRV), пульс покоя, пульс, сон (длительность и фазы), SpO₂, шаги,
VO₂ max — каждый как «опорный показатель для интерпретации самочувствия», ничего из этого
не связывается с личностью (аккаунта нет) и не покидает устройство иначе, чем в составе
запроса на разбор.
