# VIA-L — аудит паттернов и метрик: доходят ли данные до ИИ + полнота KB-как-используется

Метод (две оси на каждый элемент, как в циклах фаз/давления):
- **A. Данные доходят до ИИ?** — поле собирается в `data` (клиент) И выписывается в промпт воркера.
- **B. Покрытие KB?** — паттерн/тема есть в **велнес-KB** (VIA-L = tier `pro` → `WELLNESS_SYSTEM_PROMPT + WELLNESS_KB`),
  а не только в клиническом (EXPERT/ELITE).

Файлы: детектор `selectKBPatterns` (`cloudflare-worker.js` ~L3512), впрыск `kbBlock` (~L4196,
«Используй из базы знаний: …» — для ЛЮБОГО тарифа), велнес-KB `WELLNESS_KB` (~L720),
объект `data` (`interpreter-via-l.html` ~L7165).

Статус: **сбор паттернов — 2026-07-22** (метрики опросника — следующий шаг).

## 2. Найденные дыры (ранжировано)

### ✅ A. [ЗАКРЫТО 2026-07-22] Велнес-KB неполон: P-F19, P-F20, P-F21 отсутствовали
`selectKBPatterns` выбирает их для VIA-L женщин (аноректальные/тазовые/грудные сигналы),
`kbBlock` пишет в промпт «Используй из базы знаний: P-F20», а в `WELLNESS_KB` этого паттерна нет →
**висячая ссылка** (тот же баг, что чинили для P-F1–18, коммент L717). Модель либо игнорит (теряет
тему), либо галлюцинирует. **Фикс:** добавить велнес-формулировки P-F19/20/21 в `WELLNESS_KB`.

### ✅ B. [ЗАКРЫТО 2026-07-22] P-M10 (простата/ДГПЖ) был мёртв в VIA-L
Детектор ждёт `data.urology` с токенами `nocturia/weak_stream/incomplete_emptying/frequency`, а VIA-L
собирает урологию в `horm_male` (id `hmy_noct/hmy_stream…`, токены `night_waking/fluid_flow…`) и НЕ
кладёт в `data.urology`. Итог: `uro=[]`, токены не совпадают → P-M10 не срабатывает никогда.
**Фикс:** прокинуть уро-ответы в `data.urology` с нужными токенами (или расширить `has(...)` детектора
на horm-токены).

### ✅ C. [СНЯТО 2026-07-22] P-F19/P-F20 детекторы на самом деле живые
Сверка токенов: P-F19 ловится через `gi_slow` (есть у VIA-L), P-F20 — через gsm `support_shift`/
`tone_shift` (gsm6/gsm7, есть). Оба срабатывают для женщин. «Вход неполный» касался лишь части
токенов (uro/hemorrhoids), но основной путь работает. Отдельного фикса не требуется.

### 🟢 D. Ожидаемо (не баг): labs нет в VIA-L
P-F16 (нужен `labs.tsh`) в VIA-L почти не сработает; P-F6/F12/F18 имеют лаб-путь + симптомный/
возрастной фолбэк (работает). Лаб-ввода в VIA-L нет by design — не чиним, но помним.

### ✅ Уже починено (прошлый шаг)
Приливы (hf_count/intensity) + тазовое дно (gsm) теперь выписываются в дневной промпт;
перименопаузальная линза + грамматика метрики добавлены.

## 3. Метрики опросника — ПРОВЕРЕНО (2026-07-22): чисто, мёртвого груза нет
Промпт `_feed` собирается из НЕСКОЛЬКИХ блоков — каждое поле `data` доходит до ИИ:
- **РЕФЕРЕНСНЫЕ НОРМЫ** (~L4289): hrv, ЧСС покоя, глубокий сон, **resp_rate**, качество сна.
- **ДАННЫЕ КЛИЕНТА** (~L4305): пол/фаза/возраст/вес/рост/ИМТ/талия/WHtR, HRV+тренд, сон/глубокий/
  пробуждения, приливы, дыхание/пульс, **энергия/тревога/настроение/раздражительность**, температура/
  стресс/алкоголь, **симптомы**.
- **ПОЛНЫЕ ДАННЫЕ АНКЕТЫ / fullDataBlock** (~L4224): цель, питание/аппетит/тяга/белок/аллергии, ясность/
  туман, активность, добавки, лекарства, хрон.стресс/кортизол, гормональные симптомы, цикл+ПМС+**приливы+
  gsm**, кости, **АД**, мужское.
- **ЖАЛОБЫ ПО СИСТЕМАМ** (`complaintsContext` ~L4340): gsm / ЖКТ-проктология / **грудь** / уро.

Первичная «дыра resp_rate/mood/anxiety/breast» была артефактом (смотрел 45 строк fullDataBlock, а промпт
из нескольких блоков). Проверено — доходят все.

Остаток (мелочь, не баг): `data.urology` пусто (мужские уро-ответы в horm_male) → в тексте
`complaintsContext` мужская урология не печатается, но **паттерн P-M10 теперь срабатывает** (фикс B).
Можно позже прокинуть `data.urology` для полноты жалоб-текста — не срочно.
